2D Procedural Animation with Unity DOTS — Lesson 4

Gait: When a Promise Ends

Lesson 3 ended with 80% of a walking creature: legs that plant. The missing 20% is a single decision, made over and over — when does a foot let go? Answer it with three small rules and walking simply falls out. Nobody authors a walk cycle; the walk is what stepping looks like from outside.

The foot state machine

A foot is always in one of two states. Planted: pinned to a world position — a promise being kept (the IK target simply is that spot, every frame, while the body moves past it). Swinging: airborne on its way to a new plant. The entire art of gait is the two transitions, and each is one rule.

Rule 1 — Let go when stressed (and the partner holds)

Recipe · step trigger (per planted foot, per tick) 
home   = footprint of the hip on the ground      // moves with the body
stress = |plant - home|                          // how far behind the foot fell
if (stress > comfort && partnerIsPlanted)
    beginSwing()

Each foot owns a comfort zone around its home point. The body drifts, the planted foot stays, stress grows; past the threshold, the foot asks to step. The partnerIsPlanted guard is the entire coordination system — with it, two legs cannot swing at once, so alternation emerges without any notion of left-right phase. (The other classic architecture drives pinning from a metronome — sine phase per leg, offset by π, as in Little Polygon's locomotion series. Event-driven reads as reactive and animal; phase-driven reads as regular and confident. Rain World creatures are event-driven — they respond to circumstances, not beats.)

Rule 2 — Land where you're going, not where you are

Recipe · step target 
target = home + bodyVelocity * lead              // lead in seconds, ~0.1–0.3
target = clampToReach(target, hip, L1 + L2)      // Lesson 3's annulus, again

With lead = 0 the foot lands at its home point — already stressed the moment it arrives, condemned to step again immediately. Leading the target by a fraction of a second of velocity plants the foot ahead, buying it a full comfortable stride of body travel before it must let go again. This one dial fixes most limping. (Little Polygon calls it step extrapolation; every good stepper has it under some name.)

Rule 3 — Swing on an arc, on a clock

Recipe · the swing (fixed duration) 
t      = elapsed / duration                      // 0 → 1, then re-plant
tEase  = smoothstep(t)                           // t² (3 - 2t)
foot.x = lerp(from, target, tEase)
foot.y = ground - stepHeight * 4t(1 - t)         // parabolic lift

The parabola 4t(1−t) peaks at ½ and touches zero at both ends — lift-off and landing are automatically soft. Fixed duration (not fixed speed) keeps the rhythm stable: faster bodies don't swing faster, they step more often. Which is the punchline of this whole lesson: step frequency is emergent. You never author "walk" or "run" — you tune comfort, lead, and duration, and the gait that appears at each speed is a consequence.

Strain is a signal, not just a bug

When the body outruns the rules — a swing too slow, a comfort zone too wide — the required foot position exceeds L1+L2 and Lesson 3's reachability clamp drags the planted foot off its promise. The playground paints that leg red. A blip of red at a hard turnaround is animal (real legs strain when pivoting); sustained red is a broken gait. Learn to read the difference — it's your main debugging sense for steppers.

Mapping it to DOTS

DOTS mapping

Gait is the system upstream of Lesson 3's IK: it owns each leg's state machine and writes Limb2Bone.Target. Branchy, but branchy over two enum states on a handful of legs — Burst is fine with this. 

public enum FootState : byte { Planted, Swinging }

public struct GaitLeg : IBufferElementData        // a creature has 2..N legs
{
    public FootState State;
    public float2 Plant;        // world promise while Planted
    public float2 SwingFrom;
    public float2 SwingTo;
    public float  SwingT;       // 0..1
    public float2 HomeOffset;   // hip → home, creature-local
    public sbyte  PartnerIndex; // coordination = "is my partner planted?"
}

public struct GaitSettings : IComponentData
{
    public float Comfort, StepDuration, StepLead, StepHeight;
}

// GaitSystem (runs before the IK system), per leg:
switch (leg.State)
{
    case FootState.Planted:
        float2 home = hip + leg.HomeOffset;
        if (math.distance(leg.Plant, home) > s.Comfort &&
            legs[leg.PartnerIndex].State == FootState.Planted)
        {
            leg.SwingFrom = leg.Plant;
            leg.SwingTo   = ClampToReach(home + bodyVel * s.StepLead, hip);
            leg.SwingT    = 0; leg.State = FootState.Swinging;
        }
        ikTarget = leg.Plant;
        break;

    case FootState.Swinging:
        leg.SwingT += dt / s.StepDuration;
        if (leg.SwingT >= 1f) { leg.Plant = leg.SwingTo; leg.State = FootState.Planted; }
        float t = math.smoothstep(0, 1, leg.SwingT);
        ikTarget = math.lerp(leg.SwingFrom, leg.SwingTo, t);
        ikTarget.y -= s.StepHeight * 4 * leg.SwingT * (1 - leg.SwingT);
        break;
}

Tick order for the full creature, all four lessons composed: body/verlet + muscles → gait (writes IK targets) → IK solve → pins → hard sweeps. Note what gait state costs: two floats2 and an enum per leg — a thousand walkers is nothing. Per-creature GaitSettings variation (±20% comfort/duration) makes a crowd read as individuals.

Where to go deeper

Primary source: David Rosen's An Indie Approach to Procedural Animation (GDC 2014, free on the Internet Archive) — the canonical "tiny rules, emergent motion" talk; his walkers use a handful of poses plus exactly the kind of logic you just built. Then Little Polygon's locomotion series for the phase-driven alternative with excellent interactive figures, and rewatch the lizard sections of the Rain World talk — you'll now recognize event-driven stepping under every creature.

Compressed rules: gait cheatsheet · new terms in the glossary.

Suggested real-world rep — the graduation build: you now hold every part of a Rain World-class creature. Assemble one: a muscled verlet chain body (L2), two Limb2Bone legs (L3), gait driving the targets (this lesson), feet pinned into the body's constraint solve (L1). Then spawn fifty with ±20% settings variation and watch a species emerge. This build is the seed of your toolkit package — keep the components clean.

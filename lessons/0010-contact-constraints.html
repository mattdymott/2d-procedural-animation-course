2D Procedural Animation with Unity DOTS — Lesson 10

Contact Constraints: World Promises

Your lizard can now keep promises to itself. This lesson lets it keep a promise to the world: a spine point may touch the ground, but it must never be inside it. Collision is not a separate physics universe. In a position-based creature, it is one more constraint.

The one idea: contact is a one-sided constraint

A distance constraint says “be exactly this far apart.” A contact says “be at least this far outside the wall.” That asymmetry is the whole idea. It is a unilateral constraint: dormant while legal, active only for penetration, and it only pushes outward. A contact that pulls toward the ground is glue, not collision.

This is why the technique fits your Verlet body so naturally. You already correct positions into legality. A wall simply supplies a surface normal and the nearest legal point. The position-based dynamics paper formalizes the same advantage: collision constraints can be resolved by projecting penetrations to valid locations.

The recipe: project, then preserve the right velocity

Recipe · point against a ground or wall 
// n = outward normal; d = signed distance from p to the surface
penetration = radius - d
if (penetration > 0) {
    p += n * penetration               // position is legal now

    v  = p - prev                      // Verlet's implied velocity
    vn = dot(v, n)                     // normal: into or away from surface
    vt = v - n * vn                    // tangent: along the surface
    if (vn < 0) vn = 0                 // no velocity into a solid
    prev = p - (n * vn + vt * (1 - friction))
}

The projection fixes where the point is. Updating prev fixes what it tries to do next frame. Remove the into-wall normal velocity; damp only the tangent when you want friction. Leave tangent velocity alone for ice, reduce it for a sticky crawl.

Contacts belong inside the hard solve

A wall correction changes a spine link’s length. A distance sweep can then push that same point back into the wall. So do not save collision for a final cosmetic cleanup. Interleave it with the hard constraints:

integrate → muscles → repeat N times {
    solve distance constraints
    project contacts
    clamp joint limits
} → presentation

The playground: place the contact in the solve

Choose the next operation until the solver is complete. The readout tells you whether the chain can be both legal and the right length. This is the exact reasoning you use when a tail buzzes against a tile edge.

Joint limits use the same shape

A 2D joint limit is another one-sided correction. Compute the signed angle from parent link to child link. If it lies within [minAngle, maxAngle], do nothing. If it escapes, clamp the angle and rotate the child endpoint onto that boundary, preserving its distance to the joint. Do not “spring toward” the limit while legal: that makes the creature prefer a pose instead of merely refusing an impossible one.

Contact order in the creature tick

L9’s hard-resolve stage grows internally: distance → contacts → joint limits, repeated for a small fixed number of sweeps. Presentation still reads the result last. A filtered sprite cannot fix penetration.

Mapping it to DOTS

DOTS mapping

Keep terrain queries out of the innermost chain math. Gather a small contact description first (ground plane, tile edge, or collision normal), then run the hot per-creature buffer loop with that data. For a world raycast, gather in a prior job or use a physics query strategy appropriate to your project; the creature solve itself remains self-contained.

public struct ContactPlane : IBufferElementData
{ public float2 Point, Normal; public float Friction; }

// inside ConstraintResolveSystem, per creature, per sweep:
SolveDistances(ref spine);
ProjectContacts(ref spine, contacts);   // only moves penetrating points out
ClampJointLimits(ref limbs, limits);    // only moves out-of-range joints in
// presentation runs after this system and never writes spine/limb buffers

Treat authoring limits and friction as baked configuration; penetration, previous position, and current contact state are runtime state. That preserves L8’s config/state split while making terrain another deep module seam.

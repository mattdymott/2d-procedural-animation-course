FABRIK: Promises for Any Number of Joints

Lesson 3's triangle solves two bones exactly — and stops there. A tail that grabs a ledge, a tongue that snags a fly, a six-segment limb: for n joints you need FABRIK. The good news is startling: you already know this algorithm. You've been running its inner loop since Lesson 1.

The algorithm you already know

FABRIK (Forward And Backward Reaching Inverse Kinematics, Aristidou & Lasenby 2011) never touches an angle or a matrix. Its whole move: place each joint on the line toward its neighbour, at bone length — which is precisely Lesson 1's distance constraint. The only new idea is sweeping with intent, in two passes:

PassWhat it doesIn course terms
Backward Teleport the tip onto the target, then walk tip→root re-fixing every bone length Pin the tip where you wish it were; let one constraint sweep propagate the consequences
Forward Teleport the root back onto its anchor, walk root→tip re-fixing lengths Re-honor the root's promise; sweep the correction the other way

One backward+forward round trip = one iteration. Repeat until the tip is within tolerance of the target. Each round trip splits the remaining error between both ends' demands, and it converges fast — the paper shows it beating CCD and Jacobian methods on both cost and quality. (Alternating sweep directions converging faster than one-way sweeps — you met that note in the verlet cheatsheet. FABRIK is that trick, weaponized.)

Recipe · FABRIK (2D, uniform bone length) 
if length(target - root) ≥ totalLength:          // unreachable:
    lay chain straight from root toward target   // point at it, done (1 pass)
    return

repeat up to maxIters:
    // backward: tip → root
    p[n-1] = target
    for i = n-2 .. 0:
        p[i] = p[i+1] + normalize(p[i] - p[i+1]) * rest

    // forward: root → tip
    p[0] = root
    for i = 1 .. n-1:
        p[i] = p[i-1] + normalize(p[i] - p[i-1]) * rest

    if length(p[n-1] - target) < tolerance: break   // early-out

Warm starts: the working secret

Textbook analyses ask how many iterations FABRIK needs from a cold pose. Wrong question for games. You solve every frame, starting from last frame's pose — and the target rarely moves far in 16 ms. Started warm, the chain is nearly solved before you begin: in this lesson's playground, a moving target is tracked to sub-pixel error at one iteration per frame, and with the tolerance early-out a cap of 10 averages ~1.2. That's the honest cost of FABRIK at scale: one or two length-fixing sweeps over a handful of points. Cheaper than most muscles.

The strength dial: wish ⇄ promise, unified

FABRIK returns a solution pose — where the chain would be if the tip's promise were kept. You don't have to snap to it. Blend toward it like any muscle:

Recipe · the grab muscle 
solution = fabrik(currentPose, target)
for each point i:
    p[i] += (solution[i] - p[i]) * grabStrength    // 0..1

At grabStrength = 1 the tail grabs — a promise. At 0.3 it reaches — a wish, with gravity and momentum still voting. One dial spans the entire course vocabulary, and it can change per moment: a Rain World-style creature runs its tail at 0.2 (drapes, flows) until the moment it leaps and the tail whips to 1.0 on a grab point. Then the constraint sweeps legalize whatever the blend produced, as always — muscles propose, constraints dispose.

Mapping it to DOTS

DOTS mapping

FABRIK on a DynamicBuffer<VerletPoint> is almost insultingly direct — the buffer's current positions ARE the warm start, and the solver is normalize-and-scale with zero trig. Solve into a scratch Span, then blend: 

public struct GrabMuscle : IComponentData
{
    public float2 Target;
    public float  Strength;      // 0..1, the wish⇄promise dial
    public int    MaxIters;      // 1-4 is plenty warm-started
    public float  Tolerance;     // e.g. 0.25f
}

// inside the chain job, after integration + other muscles, before sweeps:
Span<float2> sol = stackalloc float2[pts.Length];
for (int i = 0; i < pts.Length; i++) sol[i] = pts[i].Position;

float2 root = anchor.Position.xy;
if (math.distance(g.Target, root) >= s.RestLength * (pts.Length - 1))
{
    float2 dir = math.normalizesafe(g.Target - root);
    for (int i = 0; i < sol.Length; i++) sol[i] = root + dir * (s.RestLength * i);
}
else
{
    for (int it = 0; it < g.MaxIters; it++)
    {
        sol[^1] = g.Target;                                   // backward
        for (int i = sol.Length - 2; i >= 0; i--)
            sol[i] = sol[i+1] + math.normalizesafe(sol[i] - sol[i+1]) * s.RestLength;
        sol[0] = root;                                        // forward
        for (int i = 1; i < sol.Length; i++)
            sol[i] = sol[i-1] + math.normalizesafe(sol[i] - sol[i-1]) * s.RestLength;
        if (math.distancesq(sol[^1], g.Target) < g.Tolerance * g.Tolerance) break;
    }
}

for (int i = 0; i < pts.Length; i++)                          // grab muscle blend
{
    var p = pts[i];
    p.Position += (sol[i] - p.Position) * g.Strength;
    pts[i] = p;
}

Notes: stackalloc keeps it allocation-free in Burst; chains are short, the stack doesn't care. Because the verlet buffer warm-starts the solve, MaxIters of 2 with early-out is production-honest. And since the blend happens before the hard sweeps, a mid-solve pose can never tear the body — same guarantee as every muscle.

Suggested real-world rep: give your graduation-build creature a tail with a GrabMuscle. Idle: strength 0.2, target drifting behind the body (flow). On command: strength 1.0, target on a ledge point (grab). The moment you feel the difference between those two states in play, you own the wish⇄promise spectrum. With FABRIK the toolkit's solver set is complete — what remains is the juice branch (second-order dynamics, deferred since Lesson 1) and shipping it all as a package.

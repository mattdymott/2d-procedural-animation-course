2D Procedural Animation with Unity DOTS — Lesson 1

Verlet Chains: Points on Strings

Every Rain World creature — lizards, slugcats, vulture wings — is a handful of points in space held together by distance rules. This lesson gives you that atom: the verlet chain. Master it and everything later (limbs, IK, gaits) is just decoration on top.

The idea

In his GDC talk on Rain World's animation process, Joar Jakobsson describes the approach as the opposite of frame-by-frame animation: instead of drawing poses, he places a handful of points in space and connects them at fixed distances. The simulation moves the points; the graphics simply drape over wherever the points ended up. Life emerges from physics, not from keyframes.

Two tiny recipes make this work. That's genuinely all of it.

Recipe 1 — Verlet integration

Normally you'd store position + velocity per point. Verlet stores position + previous position instead. The velocity is implied by the gap between them: if a point was at 5 and is now at 7, it's clearly moving at +2 per step. To advance, keep that drift going and add acceleration:

Recipe · integrate one point 
velocity = position - prevPosition          // implied, never stored
prevPosition = position
position += velocity * (1 - damping) + gravity * dt * dt

Why bother? Because of what comes next: we are going to directly shove points around to satisfy constraints. In a position+velocity scheme, teleporting a point desynchronizes its velocity and the system explodes. In verlet, moving a point automatically updates its implied velocity — the gap to its previous position changed. Corrections and momentum can never disagree. This is the key insight of Thomas Jakobsen's "Advanced Character Physics" (GDC 2001, built for Hitman's ragdolls), and it's why the whole genre of squishy point-creatures is stable.

Recipe 2 — Distance constraint relaxation

A chain is points plus one rule per neighbouring pair: stay exactly restLength apart. Enforce it by measuring the error and moving both points halfway toward correct:

Recipe · relax one link 
delta = b.position - a.position
error = length(delta) - restLength
correction = normalize(delta) * error * 0.5
a.position += correction
b.position -= correction

Fixing one link disturbs its neighbours, so you sweep the whole chain several times per frame. Each sweep leaves the chain a bit closer to legal. The iteration count is your stiffness dial: 1–2 sweeps gives stretchy, soupy rope; 20+ approaches a rigid stick. Rain World's floppy, imperfect feel comes from deliberately living at the low end. Pinning is even simpler: after each sweep, snap the anchored point back to where it must be. Verlet forgives the teleport.

Mapping it to DOTS

DOTS mapping

One creature = one entity = one DynamicBuffer<VerletPoint>. Chains are tiny (10–40 points) and independent, so parallelism goes across entities, not within a chain — a single Burst IJobEntity handles thousands of creatures. 

public struct VerletPoint : IBufferElementData
{
    public float2 Position;
    public float2 PrevPosition;
}

public struct ChainSettings : IComponentData
{
    public float RestLength;
    public int   Iterations;   // the stiffness dial
    public float Damping;
}

[BurstCompile]
partial struct ChainJob : IJobEntity
{
    public float  DeltaTime;
    public float2 Gravity;

    void Execute(ref DynamicBuffer<VerletPoint> pts,
                 in ChainSettings s, in LocalTransform anchor)
    {
        // 1. Integrate every point
        for (int i = 0; i < pts.Length; i++)
        {
            var p = pts[i];
            float2 vel = (p.Position - p.PrevPosition) * (1f - s.Damping);
            p.PrevPosition = p.Position;
            p.Position += vel + Gravity * (DeltaTime * DeltaTime);
            pts[i] = p;
        }

        // 2. Relax constraints, re-pinning the head each sweep
        for (int iter = 0; iter < s.Iterations; iter++)
        {
            var head = pts[0];
            head.Position = anchor.Position.xy;
            pts[0] = head;

            for (int i = 0; i < pts.Length - 1; i++)
            {
                var a = pts[i]; var b = pts[i + 1];
                float2 delta = b.Position - a.Position;
                float dist = math.max(math.length(delta), 1e-6f);
                float2 corr = delta * (0.5f * (dist - s.RestLength) / dist);
                a.Position += corr;
                b.Position -= corr;
                pts[i] = a; pts[i + 1] = b;
            }
        }
    }
}

Burst notes: the inner loop is sequential by nature (each link reads its neighbour) — don't fight it; it's ~40 points. Use a fixed timestep (run in a FixedStepSimulationSystemGroup) or damping/stiffness will vary with framerate, since dt² and iteration effects aren't time-normalized.

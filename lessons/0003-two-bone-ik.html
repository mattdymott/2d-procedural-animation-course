Two-Bone IK: Limbs That Make Promises

Lesson 2's muscles make wishes — the tip leans toward the target and physics gets a vote. Feet can't work that way: a paw that almost touches the ground reads as broken. Limbs need promises — the foot is exactly there, this frame, guaranteed. That's inverse kinematics, and for a two-bone limb the entire solver is one triangle.

The idea: two circles, one choice

A limb has a root (hip/shoulder), two bones of length L1 and L2, and a target for the foot. Ask: where can the knee be? It must sit at distance L1 from the root — a circle — and at distance L2 from the foot — another circle. The knee is where the circles intersect, and two circles intersect at two points: knee-up or knee-down. All the trigonometry below is just computing that intersection; the playground draws both circles so you can watch the algebra be geometry.

This is the classic triangle construction from Zucconi's Inverse Kinematics in 2D — root, knee, foot form a triangle whose three side lengths you already know (L1, L2, and the root→target distance), so the law of cosines hands you every angle.

The recipe

Zucconi's version outputs joint angles. For verlet bodies you want joint positions — this form returns them directly and bakes in the two clamps the tutorials skip:

Recipe · 2-bone IK, position form 
d    = max(length(target - root), ε)
dir  = (target - root) / d
d    = clamp(d, |L1 - L2| + ε, L1 + L2 - ε)   // ① reachability clamp
foot = root + dir * d                          // where the foot actually goes
cosA = (L1² + d² - L2²) / (2 · L1 · d)         // law of cosines at the root
a    = acos(clamp(cosA, -1, 1)) · bendSign     // ② bendSign = ±1 picks the knee
knee = root + rotate(dir, a) * L1
  • Clamp ① is the annulus. The reachable region isn't a disk — it's a ring. Outer edge L1+L2 (limb straight), inner edge |L1−L2| (limb folded). Unequal bones leave a dead disk around the root that the foot can never enter. Targets outside the ring get projected to its edge, which is exactly the behaviour you want: too far → limb straightens toward it, too close → folds.
  • bendSign is a modelling decision, not math. Knees bend one way, elbows the other; a creature's silhouette lives in this bit. Flip it at the wrong moment mid-animation and the knee snaps through the leg — pick per limb, change rarely and deliberately.

Promises and wishes, together

IK doesn't replace Lesson 2 — it completes it. The pattern for a full creature: verlet + muscles for everything that may flow (spine, tail, ears), IK for everything that must land (feet, grabbing hands). They meet through pins: solve the limb analytically, then write knee and foot into the verlet body as strength-1 pins (Lesson 1), and let the constraint sweeps drag the soft body along behind the planted foot. Rain World's lizards are exactly this marriage — floppy chain spines with feet that grip like promises.

Mapping it to DOTS

DOTS mapping

The solver is a pure, branch-light, allocation-free function — the friendliest thing you can hand Burst. No iteration, no convergence, identical cost every call: thousands of limbs are trivially cheap and perfectly deterministic. 

public struct Limb2Bone : IComponentData
{
    public float2 Root;       // written by the body system each tick
    public float2 Target;     // written by AI / gait logic
    public float  L1, L2;
    public float  BendSign;   // +1 or -1, a per-limb modelling choice
    public float2 Knee, Foot; // solver output, read by rendering/pins
}

[BurstCompile]
public static void Solve(ref Limb2Bone limb)
{
    const float eps = 1e-4f;
    float2 toT = limb.Target - limb.Root;
    float  d   = math.max(math.length(toT), eps);
    float2 dir = toT / d;
    d = math.clamp(d, math.abs(limb.L1 - limb.L2) + eps,
                      limb.L1 + limb.L2 - eps);

    limb.Foot = limb.Root + dir * d;

    float cosA = (limb.L1 * limb.L1 + d * d - limb.L2 * limb.L2)
               / (2f * limb.L1 * d);
    float a = math.acos(math.clamp(cosA, -1f, 1f)) * limb.BendSign;

    math.sincos(a, out float s, out float c);
    float2 rotated = new float2(dir.x * c - dir.y * s,
                                dir.x * s + dir.y * c);
    limb.Knee = limb.Root + rotated * limb.L1;
}

System order matters more than the solver: body/verlet system writes Root, gait/AI writes Target, then the IK system solves, then pins feed Knee/Foot back into the verlet buffer before its constraint sweeps. One tick, one direction of data flow, no lookups mid-job.

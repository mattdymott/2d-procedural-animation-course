2D Procedural Animation with Unity DOTS — Lesson 2

Muscles: A Rule Broken on Purpose

Your Lesson 1 chain was a corpse: constraints kept it legal, gravity did the rest. A creature is a chain that wants things. This lesson adds muscles — and in a constraint world, a muscle is beautifully simple: a rule broken on purpose, weakly.

What a muscle is

Lesson 1's distance constraint corrects 100% of its error every sweep — that's what makes it a bone. Jakobsen's paper hides a gem in one line: correct only a fraction of the error and the same code becomes a spring. That fraction is muscle strength. A weak pin is a wish; a strong pin is a bone. Everything below is this one trick pointed at three different wishes:

MuscleThe wishGives the creature
Goal"Tip, be at the target"Intent — reaching, tracking, grabbing
Rhythm"Body, wave side to side"Life — idle motion, swimming, breathing
Tone"Spine, stay straight-ish"Posture — stands up instead of puddling

Recipe 1 — Goal: the weak pin

Recipe · reach muscle (per frame, on the end point) 
tip.position += (target - tip.position) * strength   // strength 0..1

A pin (Lesson 1) is this with strength = 1. At 0.15 the tip leans toward the target while gravity, momentum, and the rest of the body all still get a vote — that negotiation is the organic look. Verlet makes it safe: the shove coherently updates the implied velocity, so the whole chain follows the tip like a body, not like a rubber band glued to a dot.

Recipe 2 — Rhythm: the traveling wave

Recipe · wave muscle (per frame, each interior point) 
dir   = normalize(p[i+1] - p[i-1])          // local body direction
perp  = (-dir.y, dir.x)
phase = time * speed - i * phasePerLink      // - i·k makes the wave TRAVEL
p[i] += perp * amplitude * envelope(i) * sin(phase)

Shove each point sideways — perpendicular to its own body — by a sinusoid whose phase lags along the chain. The lag is everything: without -i·k the body rocks stiffly in unison; with it, an undulation travels base-to-tip and reads as swimming. The envelope shapes where the muscle lives: the playground uses 1 − i/n (strong at the base, silent at the tip) because a rhythm that reaches the tip fights the goal muscle for control of it — you'll feel this in Challenge 2.

Recipe 3 — Tone: posture springs

Recipe · tone muscle (per frame, each interior joint) 
// a distance constraint between GRANDPARENT neighbours i-1 and i+1,
// rest length 2·restLength (= perfectly straight), corrected by only `tone`
delta = p[i+1] - p[i-1]
corr  = delta * (tone * 0.5 * (length(delta) - 2*restLength) / length(delta))
p[i-1] += corr;  p[i+1] -= corr

Skip-one constraints punish bending: the straighter the chain, the closer i−1 → i+1 is to two full links. At tone = 1 you get a rod; at 0.2 a tired tentacle that sags but doesn't puddle. This is the same idea Rain World uses to give lizard spines their stiff-but-swishy character — bodies in the GDC talk are exactly chains with tuned resistance to bending.

Order of operations — muscles propose, constraints dispose

Each fixed tick: 1) integrate, 2) fire every muscle once (weak, partial corrections), 3) run the hard constraint sweeps + pins from Lesson 1. The skeleton always gets the last word, so muscles can never tear the body apart — crank any slider to max and the creature stays whole. That guarantee is why this architecture is fearless to tune.

Mapping it to DOTS

DOTS mapping

Muscles are pure per-entity data driving a few extra loops inside the same ChainJob from Lesson 1 — no new sync points, still one IJobEntity across thousands of creatures. 

public struct TentacleMuscles : IComponentData
{
    public float2 ReachTarget;      // set by AI/steering systems
    public float  ReachStrength;    // 0..1 fraction per fixed tick
    public float  Tone;             // 0..1 posture spring strength
    public float  WaveAmplitude;    // px per tick, pre-envelope
    public float  WaveSpeed;        // rad/s
    public float  WavePhasePerLink; // rad, the travel term
    public float  Phase;            // advance by WaveSpeed * dt each tick
}

// Inside ChainJob.Execute, between integration and the constraint sweeps:
m.Phase += WaveSpeed * DeltaTime;

for (int i = 2; i < pts.Length - 1; i++)          // rhythm
{
    float2 dir  = math.normalizesafe(pts[i+1].Position - pts[i-1].Position);
    float2 perp = new float2(-dir.y, dir.x);
    float env   = 1f - (float)i / (pts.Length - 1);
    var p = pts[i];
    p.Position += perp * (m.WaveAmplitude * env *
                  math.sin(m.Phase - i * m.WavePhasePerLink));
    pts[i] = p;
}

var tip = pts[pts.Length - 1];                     // goal
tip.Position += (m.ReachTarget - tip.Position) * m.ReachStrength;
pts[pts.Length - 1] = tip;

for (int i = 1; i < pts.Length - 1; i++)          // tone
{
    var a = pts[i-1]; var c = pts[i+1];
    float2 d = c.Position - a.Position;
    float len = math.max(math.length(d), 1e-6f);
    float2 corr = d * (m.Tone * 0.5f * (len - 2f * s.RestLength) / len);
    a.Position += corr; c.Position -= corr;
    pts[i-1] = a; pts[i+1] = c;
}

The strengths are fractions per fixed tick — they only mean anything at a fixed timestep, one more reason this all lives in FixedStepSimulationSystemGroup. Per-creature variation is now trivially data: randomize Tone/WaveSpeed slightly at spawn and a swarm of identical tentacles stops looking cloned.

2D Procedural Animation with Unity DOTS — Lesson 15

Creature Authoring: Rules In, Preview Out

A creature editor should let you see and change the rules that produce motion. It should not serialize yesterday’s simulation or quietly turn a preview into the runtime authority.

The one move: author the recipe, derive the picture

Give a designer a small, meaningful blueprint: body segment count and length, leg reach, and comfort radius. From that blueprint, derive scene handles, guide lines, and a rest-pose preview every editor repaint. The preview is disposable; the blueprint is the only authored truth.

Recipe · one-way authoring data flow
// Saved and baked: stable inputs a designer can intentionally change.
[Serializable]
public struct CreatureBlueprint
{
    public int BodySegments;
    public float SegmentLength;
    public float LegReach;
    public float StepRadius;
}

// Editor-only: derive visuals from the serialized blueprint.
serializedObject.Update();
DrawCreaturePreview(blueprint);              // handles, guides, labels
DrawEditableRadiusHandle(stepRadiusProperty);
serializedObject.ApplyModifiedProperties();  // edits + Undo

// Never save or edit these as authoring data:
// previousPosition, currentWorldPlant, gaitPhase, solverIteration

Unity’s Gizmos and Handles guidance calls out scene handles as tools for editing procedurally generated or invisible content. Pair them with SerializedObject.ApplyModifiedProperties: edits flow back to serialized targets with Undo recorded, while your runtime starts cleanly from baked configuration.

Scene handles are a view, not another model

LayerOwnsMay persist?
BlueprintIntentional, inspectable creature parametersYes—serialize and bake.
Editor previewRest skeleton, reach circles, labels, warningsNo—derive every repaint.
Runtime stateVerlet history, plant relation, gait phase, solver stateNo—initialize or simulate after baking.

This is Lesson 8’s config/state split applied to tools. It keeps a scene handle from becoming a second source of truth, and keeps a paused, half-solved creature from becoming an asset default. A useful editor tool makes the invisible legible; it does not make the transient authoritative.

DOTS mapping

Treat the authoring component as the front door to the package. Its Baker copies only blueprint fields into immutable config components and allocates predictable runtime state separately. Preview code stays in an Editor assembly and uses the same pure geometry helpers where possible, but it never reads a live world to decide what the asset means.

// Baker: stable recipe crosses the authoring/runtime boundary.
AddComponent(entity, new ChainConfig
{
    SegmentCount = authoring.BodySegments,
    RestLength   = authoring.SegmentLength,
});
AddComponent(entity, new GaitConfig
{
    LegReach = authoring.LegReach,
    StepRadius = authoring.StepRadius,
});

// Runtime systems create and evolve their own positions, phases and plants.

A second authoring lesson can add validation: warn when a requested leg reach cannot satisfy the two-bone annulus, before entering Play mode.

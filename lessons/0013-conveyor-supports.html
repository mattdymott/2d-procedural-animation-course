Conveyors: A Support Has Two Motions

Lesson 12 made a planted foot ride a moving platform. A conveyor exposes the missing distinction: a support transform can stand still while its surface material travels. A planted promise needs both motions.

The one move: add surface travel in support space

A relative plant already stores a support entity and local point. For a belt, retain that landing point and add a small SurfaceOffset. While the foot is planted, integrate the belt’s local material velocity into that offset, then transform the sum to world. This is still one committed relationship—there is no fresh terrain query.

Recipe · planted on a moving conveyor
// landing: gait makes one commitment
leg.Support       = hit.Entity;
leg.LocalPlant    = InverseTransformPoint(hit.Entity, hit.Point);
leg.SurfaceOffset = float2.zero;

// planted ticks: support pose + surface travel define the target
leg.SurfaceOffset += support.BeltVelocityLocal * dt;
localTarget        = leg.LocalPlant + leg.SurfaceOffset;
leg.WorldPlant     = supportPose.TransformPoint(localTarget);
ik.Target          = leg.WorldPlant;

// liftoff: retain motion for the next body / swing decision
carryVelocity = supportPose.PointVelocity(localTarget)
              + supportPose.TransformDirection(support.BeltVelocityLocal);

A transform moves coordinates; a conveyor moves material through coordinates. A rotating platform needs only the first term. A stationary belt needs only the second. A rotating belt needs both. Gait still decides when the foot plants and releases; the support adapter only evaluates the already-committed promise.

Carry velocity is for continuity, not a new owner

When a foot leaves a conveyor, the character has inherited some motion from it. Sample the support-point velocity plus the belt’s world direction at liftoff, then hand that value to body/locomotion prediction. Do not let the renderer invent it, and do not let a new raycast rewrite the final planted tick.

Keep the distinction in compact data. A support adapter reads cached pose and surface-velocity data; the hot gait loop integrates only float2s. Gather support data once per chunk or region, then evaluate each relative plant in parallel.

public struct GaitLeg : IBufferElementData
{
    public Entity Support;
    public float2 LocalPlant;
    public float2 SurfaceOffset;       // zero for ordinary platforms
    public float2 WorldPlant;
}

// While planted. SupportAdapter owns these reads; gait owns phase changes.
leg.SurfaceOffset += belt.VelocityLocal * deltaTime;
leg.WorldPlant = pose.TransformPoint(leg.LocalPlant + leg.SurfaceOffset);

Unity’s TransformPoint documentation makes the coordinate half explicit: local positions become world positions, while directions need a direction conversion instead. Your ECS pose adapter applies the same distinction.

Where to go deeper

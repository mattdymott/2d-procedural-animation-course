Cadence Switching: Change the Rule, Not the Plants

A wave gait suits a careful crawl; alternating tripods suit a faster stride. The creature can request either from movement intent, but it must not reset feet mid-swing just because speed changed.

Separate requested from active cadence

Recipe · defer a policy change safely
GaitCadence requested = desiredSpeed >= settings.TripodEnter
    ? GaitCadence.Tripod
    : GaitCadence.Wave;

if (requested != gait.Active)
    gait.Pending = requested;

if (gait.Pending != gait.Active && NoLegIsSwinging(legs))
{
    gait.Active = gait.Pending;
    SeedPolicyFromCurrentPlants(legs); // preserve plants; do not replant
}

Use separate enter and exit thresholds so a creature near one speed does not flip cadence every tick. Turning or hazards may request the more careful policy too, but the safety boundary stays the same: wait for an honest synchronization point.

DOTS mapping

Keep one gait module and one leg buffer. The cadence enum and pending state are compact mutable state, while speed thresholds are baked configuration. Policy helpers decide permission; the common plant/swing implementation remains shared.

public enum GaitCadence : byte { Wave, Tripod }

public struct CadenceState : IComponentData
{
    public GaitCadence Active;
    public GaitCadence Pending;
}

Where to go deeper

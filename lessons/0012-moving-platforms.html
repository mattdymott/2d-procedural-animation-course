Moving Platforms: Relative Promises

A planted foot promised a world point. That was perfect for static ground. On an elevator, the promise is still correct — but its coordinate system was wrong. Store the foot relative to its support, then let the support carry it through the world.

The one move: plant in the support’s space

When L11 accepts a foothold on static terrain, Plant can be a world point. When it accepts a hit on a moving platform, record two things: the support entity and the hit point transformed into the support’s local space. Every planted tick, transform that local point back to world and feed it to IK. The foot remains absolutely still relative to the platform, which is the promise the player sees.

Recipe · dynamic support
// landing: gait owns this one commitment
leg.Support    = hit.Entity
leg.LocalPlant = InverseTransformPoint(hit.Entity, hit.Point)

// planted ticks: support transform supplies current world target
leg.WorldPlant = TransformPoint(leg.Support, leg.LocalPlant)
ik.Target      = leg.WorldPlant

// liftoff: clear Support; SwingFrom and SwingTo are world positions

Do not freeze the original world point: the platform leaves and the leg strains backward. Do not re-query every planted frame: the foot follows sensor jitter. A relative plant is stable state, not a constantly recomputed decision.

That split is why a moving platform does not need to infect gait with transform hierarchy details. Gait has a small support adapter; the rest of its state machine remains the one you tested in Lesson 4.

DOTS mapping

Represent a support relation explicitly, rather than hiding it inside a world-space target. In a production package the adapter reads an entity’s current transform (or platform pose snapshot) and converts LocalPlant to world before IK. Keep platform velocity available too: at liftoff, use it as part of the body-relative lead calculation if that serves your game.

public struct PlantSupport : IComponentData
{ public Entity Value; }                // enabled only while planted on dynamic support
public struct GaitLeg : IBufferElementData
{ public float2 LocalPlant, WorldPlant; public Entity Support; /* phase ... */ }

// no new gait decision per tick:
if (leg.State == FootState.Planted && leg.Support != Entity.Null)
    leg.WorldPlant = supportPose.TransformPoint(leg.LocalPlant);

Unity’s transform APIs distinguish local-to-world point conversion from direction conversion; positions are affected by translation (and scale), directions are not. The equivalent principle applies to your ECS pose adapter. [Unity TransformPoint documentation]

Batching at Scale Cheatsheet

Patterns for running thousands of procedural creatures. Taught in Lesson 7. Assumes DOTS fluency — these are the animation-specific traps, not ECS basics.

The budget

per-creature cost × count ≤ your frame slice. 60fps = 16.6ms shared with render + gameplay. Every pattern shrinks one factor: the cost, or the count paid at full price.

Five patterns

#PatternDo
1Parallelize across, not withinOne creature = one entity = one IJobEntity iteration. Chains are sequential internally; leave them so.
2Self-contained creaturesPin feet into own buffer; no ComponentLookup random access in hot jobs. Cross-entity needs? Snapshot in a prior job.
3Structural change is the enemy"dead"/"swinging"/"grab-active" as IEnableableComponent. Toggle in place — no archetype move, no ECB, no sync point. Pool, don't destroy.
4Keep buffers in-chunkSize [InternalBufferCapacity] to typical chain length. Overflow spills to heap AND wastes the inline slot — double cache penalty, forever.
5Branchless inner loopsgait switch + IK bendSign → math.select / sign multiplies / masks, so Burst keeps the solver SIMD-wide.

Simulation LOD — the multiplier

near (on-screen, large): full iterations, every frame
far  (distant, tiny):    iters capped low, updated every Nth frame,
                         round-robined by entity index to spread cost

// enableable tier flag = no structural change to retier
struct FarLOD : IComponentData, IEnableableComponent {}

if (far.ValueRO) {
    if ((e.Index & 3) != frameParity) return;   // ~1/4 frames, index-spread
    iters = min(iters, 2);
}

Small near-band at high fidelity + cheap amortized far-band turns 50ms frames into 5ms. Assign FarLOD from on-screen bounds in a light culling system.
